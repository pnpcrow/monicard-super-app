# Internationalization

## Supported locales

| Code | Language |
|---|---|
| `en` | English, default and fallback |
| `ja` | Japanese |
| `zh` | Simplified Chinese |
| `ko` | Korean |
| `ru` | Russian |

## Implementation

All application strings live in `public/i18n.js`. `createI18n()` resolves dotted keys and falls back to English. Locale selection is stored in `localStorage` as `monicard-locale`.

## Rules

- New UI text must never be hard-coded in `app.js`.
- Every new key must be added to all five locales in the same change.
- Protocol identifiers such as `GET_VERSION` are not translated.
- User-generated content and device-provided strings are not translated.
- English wording should be plain and serve as the semantic source for translators.
- Layout testing must include long Russian text and compact CJK text.

## Adding a locale

1. Add the locale code to `SUPPORTED_LOCALES`.
2. Add a complete message object.
3. Add the native language name under every locale's `localeNames`.
4. Test desktop and mobile layouts.
5. Update this document and README.

## Russian tag localization

The tag master includes `ru` labels for every official China-master category/item and every community Japan-extension category/item. Empty official slots remain empty and retain their original IDs. For internationally marketed works, brands, artists, and events, the established international title is preserved when that is safer than inventing a Russian title. Community extension tags remain marked as unofficial.
